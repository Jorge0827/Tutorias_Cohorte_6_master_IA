Qué es Parquet y cómo se usa de verdad

Misma tabla que un CSV, otro formato de archivo. Pensado para análisis, no para abrirlo en Excel.

Parquet es un formato de archivo para guardar tablas. CSV guarda por filas en texto. Parquet guarda por columnas en binario comprimido.

En una frase para la clase: Parquet no es otra tabla. Es otra forma de guardar la misma tabla (df_norm) para que el siguiente análisis sea más rápido y no pierda los tipos.

1. Analogía

CSV

Fotocopia de la hoja

Cualquiera la lee: Excel, Bloc de notas, Google Sheets. Es pesada y se pierde el “formato”: las fechas vuelven a texto.

Parquet

Archivo del sistema de datos

No se abre “a ojo”. Llega más compacto, recuerda que salario es número y fecha es fecha, y puede leer solo las columnas que pides.

2. Filas vs columnas

Imagina tres empleados con nombre, depto y salario.

CSV — guarda fila completa

Ana García | Ventas | 4500
Carlos Lopez | Ventas | 3200
Valentina Cruz | TI | 7200

Si solo quieres el promedio de salario, igual tienes que leer nombre y departamento.

Parquet — guarda cada columna junta

nombres: Ana, Carlos, Valentina
deptos: Ventas, Ventas, TI
salarios: 4500, 3200, 7200

Puedes leer solo salarios. Por eso en un data lake Parquet gana a CSV.

3. Qué ganas (y qué pierdes)

CSV Parquet
Se abre en Excel Sí No (hace falta pandas, Spark, Power BI, etc.)
Conserva tipos No. fecha_ingreso vuelve a texto Sí. Sigue siendo datetime
Tamaño Más pesado (texto) Más liviano (columnar + compresión)
Lectura selectiva Lee el archivo entero Puede leer solo algunas columnas
Dependencia Ninguna En pandas: pyarrow

4. Cómo se usa en un entorno real

En la empresa casi nadie deja el resultado limpio “solo en el notebook”. El Load escribe un archivo (o una tabla) que otro sistema consume.

El flujo típico

  1. Extract: CSV sucios, API, base transaccional.
  2. Transform: limpiar, tipar, validar (tu df_norm).
  3. Load a Parquet: se guarda en un data lake (carpeta en S3, GCS, Azure, o un disco local).
  4. Consumo: Spark, pandas, Power BI, BigQuery, un modelo de ML leen ese Parquet. Nadie vuelve al CSV crudo.
Dónde lo vas a ver escrito:
  • s3://empresa-lake/gold/empleados/anio=2024/mes=03/part.parquet
  • Databricks / Spark: spark.read.parquet("...")
  • AWS Athena y Google BigQuery pueden consultar Parquet sin cargarlo a una base clásica
  • Power BI y Tableau también saben leer Parquet
Esa ruta con anio= y mes= se llama partición: no lees 5 años si solo pides marzo.

Por qué el data lake prefiere Parquet y no CSV

Un lago puede tener millones de filas. Preguntar “salario promedio de TI en Colombia” sobre CSV obliga a leer todo el texto. Sobre Parquet el motor abre la columna salario (y a veces solo los archivos de esa partición). Menos red, menos disco, menos plata en la nube.

5. En nuestro ETL (pandas)

Es el mismo DataFrame. Cambia el destino del Load.

# Escribir — fase Load
df_norm.to_parquet("output/empleados_limpios.parquet", index=False)

# Leer — el analista o el modelo, al día siguiente
df = pd.read_parquet("output/empleados_limpios.parquet")

# En un lago grande: solo las columnas que importan
df = pd.read_parquet(
    "output/empleados_limpios.parquet",
    columns=["departamento", "salario"]
)
Necesitas pip install pyarrow (o fastparquet). Si no está, to_parquet falla. El CSV sigue siendo un Load válido para entregar a Excel.

6. Cuándo usar cada uno

Usa CSV cuando…

  • Lo va a abrir una persona en Excel
  • Es una entrega pequeña (decenas o cientos de filas)
  • El receptor no tiene pandas / Spark

Usa Parquet cuando…

  • El siguiente paso es análisis o ML
  • Importan los tipos (fechas, booleanos)
  • El archivo va a un data lake o se va a leer muchas veces

7. Lo que deben recordar

  1. Parquet = tabla columnar comprimida, no una base de datos.
  2. CSV intercambia; Parquet analiza.
  3. En el Load de este curso: misma df_norm, dos archivos en output/.
  4. En la empresa: Parquet en el lago (gold) es el entregable que consume BI y ML.
